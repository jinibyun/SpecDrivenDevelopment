# BookFlow — Database Spec (db.md)

> `spec.md` §5 (Data Model)에서 분화된 문서. Neon DB(PostgreSQL)에 MCP로 직접 적용됩니다.

## 1. Entities Overview

```
Customers ──┐
            │ 1:N
            ▼
         Bookings ──N:1──▶ Services
            │
            │ 1:N
            ▼
    NotificationLogs

Admins (독립 — 인증 전용)
```

## 2. Table Definitions

### 2.1 `customers`

| Column | Type | Constraints | 설명 |
|---|---|---|---|
| id | uuid | PK, default gen_random_uuid() | |
| name | text | not null | 고객 이름 |
| phone | text | not null | 연락처 |
| email | text | nullable | |
| created_at | timestamptz | default now() | |

### 2.2 `services`

| Column | Type | Constraints | 설명 |
|---|---|---|---|
| id | uuid | PK, default gen_random_uuid() | |
| name | text | not null | 서비스명 (예: 상담 30분) |
| duration_minutes | integer | not null | 소요 시간 |
| price | integer | nullable | 원 단위, 데모에서는 표시용 |
| is_active | boolean | default true | 노출 여부 |
| created_at | timestamptz | default now() | |

### 2.3 `bookings`

| Column | Type | Constraints | 설명 |
|---|---|---|---|
| id | uuid | PK, default gen_random_uuid() | |
| customer_id | uuid | FK → customers.id, not null | |
| service_id | uuid | FK → services.id, not null | |
| scheduled_at | timestamptz | not null | 예약 일시 |
| status | text | not null, default 'pending' | pending / confirmed / cancelled / completed / no_show |
| note | text | nullable | 고객 문의사항 |
| created_at | timestamptz | default now() | |
| updated_at | timestamptz | default now() | |

**Index**: `(service_id, scheduled_at)` — 슬롯 가용성 조회 최적화

### 2.4 `admins`

| Column | Type | Constraints | 설명 |
|---|---|---|---|
| id | uuid | PK, default gen_random_uuid() | |
| email | text | unique, not null | |
| password_hash | text | not null | |
| name | text | nullable | |
| created_at | timestamptz | default now() | |

### 2.5 `notification_logs`

| Column | Type | Constraints | 설명 |
|---|---|---|---|
| id | uuid | PK, default gen_random_uuid() | |
| booking_id | uuid | FK → bookings.id, not null | |
| type | text | not null | confirmation / reminder / chatbot_reply |
| channel | text | not null | email / kakao / etc |
| sent_at | timestamptz | default now() | |
| status | text | default 'sent' | sent / failed |

## 3. Relationships

- `customers.id` 1 : N `bookings.customer_id`
- `services.id` 1 : N `bookings.service_id`
- `bookings.id` 1 : N `notification_logs.booking_id`

## 4. Seed Data (데모용 mock data)

- `services`: 3개 항목 (상담 30분 / 시술 60분 / 재방문 상담 20분)
- `customers`: 5~8명 샘플
- `bookings`: 위 조합으로 대시보드에 다양한 status가 보이도록 10~15건 생성
- `notification_logs`: bookings 생성 시 confirmation 타입으로 함께 시드

## 5. MCP 적용 순서 (라이브 데모용)

1. MCP로 Neon DB 연결 확인
2. 위 5개 테이블 생성 (`CREATE TABLE` 문서 기반 지시)
3. Seed data 삽입
4. 간단한 조회 쿼리로 결과 확인 (예: `SELECT * FROM bookings JOIN customers ...`)
